# 失败样本库

每次产出被用户退回，在这里记一条。

用途有两个：**下次动笔前先扫一遍**，避免同类错误复发；攒够十份，可以当回归测试集用。

记的时候只记事实，不记情绪。用户原话要照抄，那是判断「到底哪里不对」最准的证据。

格式：

```
## YYYY-MM-DD 报告简称（第几版）

- 违反第 X 条：具体是什么
- 用户原话：
- 修正后：
```

一条铁律：**同类问题出现第二次，说明规则没写清，回去改 `spec.md`，不要只在这里再记一条。** 失败库是补丁，规范才是防线。

---

下面两条是真实案例，随技能一起发布，兼作格式示例。

## 2026-11-12 MIT 论证图（首版）

- 违反第 18 条：每格用「标题 + 副标题」两截拼，上半句像标题、下半句像补注，读者得自己拼才能读通，整体呈碎片化。
- 用户原话：「你在这个表格中的表述太碎片化了，不够连贯清晰和一目了然，重写」
- 修正后：每格改成一句完整判断句，五句连读即一段连贯论证，删掉「第 X 步」这类标签承重。

## 2026-11-12 MIT 论证图（第二版）

- 违反第 18 条：句子仍不能脱离上下文读懂。未补主语，读者不知道「看人有多辛苦」指谁、「技术」指什么 AI、「市场」指谁。
- 用户原话：「你需要做到的是让读者就算不读上下文，光读这个句子本身，也能一目了然、秒懂」
- 修正后：「不看掌握它的人干得有多辛苦」「AI 改变手艺价值的方式有五种」「买 AI 的和卖 AI 的，都偏爱纯自动化」。
